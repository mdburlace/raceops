**Release notes** list every release of RaceOps, newest first. Open them from **Help & guide → Release notes**, or press the **Version** number at the bottom of the sidebar.

They're stored on your device with the guide, so they work offline at the track.

## What's in each release

Each release shows:

- **Summary**: what the release is about, in a sentence or two.
- **Release date** and **version**. The version is the release date, e.g. *2026.10.24*. A second release on the same day ends in *.2*.
- **New features**: things you couldn't do before.
- **Improvements**: changes to features you already use.
- **Bug fixes**: things that weren't working properly.
- **Notes**: anything to know or do for this release, such as a setting your platform admin needs to set, or closing and reopening the app.

A release leaves out a part with nothing in it.

The newest release is shown in full. Tap an earlier release for its notes, and use **‹** and **›** at the bottom to step through them.

## Which version you have

The bottom of the sidebar shows the version you're using, marked **This version** in the release notes.

After an update, Home shows **RaceOps has been updated** once, with a link to the release. Press **×** to hide it.

If the version is older than the newest release your team expects, close and reopen the app to update it. Your problem reports include the version, so we know what you were using.

## What's new and release notes

[What's new](/help/whats-new) has one line per change, with links to the guide articles it changed. Release notes go into more detail and say which release each change came in.

## Links to the code (platform admins)

A platform admin can link each release to its code on GitHub:

1. Go to **Platform admin → Settings**.
2. Type the repository's address in **Code repository**, e.g. *https://github.com/your-name/raceops*.
3. Press **Save**.

Each release then shows **Code changes on GitHub**, and **Pull request #…** when the release came from one. Leave **Code repository** empty for no links. The repository must be one people can open (a public repository, or one they've been given access to).

**Who can do this:** platform admins.
